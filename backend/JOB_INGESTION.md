# Job Scout ingestion

`POST /api/jobs/ingest` accepts:

```json
{
  "userId": "firebase-user-uid",
  "userProfile": {"full_name": "Jane Doe", "skills": ["Python"]},
  "jobData": {
    "title": "Software Engineer",
    "company": "Example",
    "location": "Remote",
    "applyUrl": "https://example.com/jobs/123"
  },
  "jdText": "Full job description text"
}
```

`userProfile` follows `UserProfile` in `models.py`; it must already be
transformed from the frontend profile format. The reusable Python entry point
is `services.job_ingestion.ingest_job(request: IngestJobRequest) -> dict`.

The service calls `generate_all_in_one(..., thinking_level="high")`, validates
its numeric 1–10 score, and returns HTTP 200 with
`{"success": false, "reason": "Match score below 9/10 threshold", "matchScore": 8.9}`
for scores strictly below 9. No Firestore client is opened for rejected jobs.
Generation runs in full before filtering. The existing generator currently
hardcodes its draft call to `medium` internally, and the Gemini wrapper does
not forward the thinking level to the SDK; passing `high` preserves the requested
call contract but does not change those existing internals.

For scores of 9 or higher, all three artifact strings must be present and nonempty.
The service creates `jobs/{autoGeneratedId}` with the request's job metadata,
`url` from `applyUrl`, `status: "Saved"`, `source: "JobScout"`,
`notes: "Auto-generated by RoleFit Job Scout"`, `matchAnalysis`, `package`, and
Firestore server timestamps for `createdAt` and `updatedAt`.
`appliedDate` is `null`, matching `tracker.addJob()` for saved jobs.
It returns HTTP 200 with `success: true`, `jobId`, `matchScore`, and
`appUrl: "https://rolefit-backend-946716696276.us-central1.run.app/tracker"`.
Each successful request creates a new job; there is no deduplication.

Errors use FastAPI's `{"detail": "..."}` shape: HTTP 422 for invalid requests,
502 for generation failures or malformed generated output, 503 for Firestore
initialization/write failures, and 500 for unexpected errors. Internal exception
details are logged on the server, not returned to the caller.

## Runtime configuration

- Install `backend/requirements.txt`, including `google-cloud-firestore`.
- Keep the existing `GOOGLE_API_KEY` configuration for Gemini.
- The Firestore client uses Application Default Credentials. On Cloud Run,
  the runtime service account needs Firestore write access to the target project.
  Locally, use ADC or set `GOOGLE_APPLICATION_CREDENTIALS` to a credential file.
- Set `FIRESTORE_PROJECT_ID` to the same project as the frontend's
  `VITE_FIREBASE_PROJECT_ID` when it differs from the default ADC project.
  The Docker image now carries the frontend build's project ID into this runtime
  variable. Local runs also fall back to `VITE_FIREBASE_PROJECT_ID` if present.
  The default Firestore database is used.
- This route follows the existing API's authentication behavior: it accepts the
  supplied `userId` without verifying ownership. Restrict callers at the service
  boundary if it is exposed to untrusted clients; server credentials use IAM,
  not frontend Firestore security rules.

Existing CORS middleware already allows POST and content-type headers.

## Tracker synchronization

`src/pages/Tracker.jsx` subscribes on mount through `tracker.subscribeJobs()` to
the default database's root `jobs` collection, filtered by exact
`userId == currentUser.uid`. It unsubscribes on unmount or account change.
Firestore snapshots drive initial loading and subsequent additions, updates,
and deletions, including backend ingestion. Listener errors show a Retry button.
The Saved column requires `status === "Saved"`; the search box also filters by
title/company. There is no source or match-score filter in the tracker.

Both `getJobs()` and the listener convert Firestore timestamps to ISO strings
and sort newest updates first. They use local estimates for pending timestamps.
If a job remains missing, confirm its `userId` equals the signed-in Firebase UID
(not the user's email) and that the frontend and backend target the same project.

## Tests

From the repository root, with `pytest` and `httpx` installed:

```sh
PYTHONPATH=backend python3 -m pytest backend/tests/test_job_ingestion.py -q
```

Tests mock Gemini and Firestore and do not incur generation costs or write data.
